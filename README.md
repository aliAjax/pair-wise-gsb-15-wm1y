# FlowDesk Studio

FlowDesk Studio 是一个完全运行在浏览器中的企业级低代码流程编排与审批监控演示平台。项目使用 React、TypeScript、Vite、Zustand 和 React Flow，所有数据均为本地 mock，不需要后端、登录或外部 API。

## 启动

需要 Node.js 20+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址（默认 `http://localhost:5173`）。建议使用 1440px 或更宽的现代桌面浏览器。

## 测试

首次运行先安装 Chromium：

```bash
npx playwright install chromium
npm test
```

Playwright 会自动启动 Vite（端口 4173），串行验证 Dashboard、编辑器审批配置、双区域校验、条件修复、动态表单预览、发布影响预检与逐项处置、异常实例实际执行版本、版本比较、撤回回退快照与带原因草稿、历史恢复。测试失败时会保留截图和 trace。

> 测试状态通过 localStorage（`flowdesk-studio-v2`）持久化，刷新后发布记录、实例版本绑定与撤回标记保持一致。

## 浏览器验证路径

1. Dashboard 点击“差旅费用审批”进入编辑器。
2. 选择“直属主管审批”，切换审批人来源并保存草稿。
3. 运行校验，观察 Condition 节点红色错误态和底部问题面板。
4. 选择“金额判断”，配置申请金额大于 5000，再次校验。
5. 打开预览，输入金额 12000，观察模拟分支切换。
6. 返回并发布：无差异时直接发布；有节点新增/移除/配置变化时打开发布影响预检，查看受影响实例清单与「流程/实例/节点/规则」冲突表，对运行中实例选择切到新版本、保留旧快照或终止（审批中、异常实例只能保留或终止），未逐项处置不能发布。
7. 进入运行监控，打开实例查看实际执行版本、按绑定快照渲染的画布与冻结规则；筛选已终止实例。
8. 从编辑器进入版本历史，查看发布记录、绑定实例数与规则快照；撤回当前版本回到上一快照，返回编辑器填写变更原因新建草稿后再改动；选择两个版本比较，或恢复旧版本为草稿。

## 项目结构

- `mock-data/`：12 个流程、80 个实例、8 个用户、6 个角色、5 个业务域及边界案例。
- `src/components/`：布局、公共状态组件和 React Flow 画布。
- `src/pages/`：Dashboard、流程列表、编辑器、表单预览、运行监控、版本历史。
- `src/store/`：Zustand 全局状态（localStorage 持久化）、校验、发布影响预检/处置发布、撤回、带原因草稿、复制、归档及恢复逻辑。
- `src/lib/`：发布影响预检纯逻辑（节点/规则 diff、实例阶段判定、冲突与受影响实例清单、规则摘要）。
- `src/components/PublishCheckModal.tsx`：发布前影响预检弹窗。
- `src/types/`：核心业务数据 TypeScript 类型（含版本规则快照、实例版本绑定、处置留痕）。
- `tests/`：关键产品链路 Playwright 测试。

## Mock 边界案例

数据集中包含空流程、孤立审批节点、缺少结束节点、未配置条件分支、审批人为空、表单必填校验、超长流程名称、超长说明展示能力、无异常实例，以及由搜索筛选产生的空结果状态。
